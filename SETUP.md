# J — setup guide (the parts only Wolf can do)

Everything in this repo is built and type-checked; the steps below connect it to live services. Do them in order.
Names used: GitHub repo `KenhighRDS/J` (this one, branch `claude/affectionate-newton-vp71k9` → merge to `main`), releases repo `KenhighRDS/j-releases` (public, to create), Supabase project `J` (to create), Firebase project `j-signals`, Netlify site `j-signals` (created: https://app.netlify.com/projects/j-signals → https://j-signals.netlify.app), Android package `com.jsignals.app`.

## 0. Repo
- Merge this branch into `main` (Netlify and the APK workflow are set up for `main`).
- Create the public repo `KenhighRDS/j-releases` with one file `latest.json` containing `{}`. The APK workflow publishes releases and rewrites `latest.json` there.
- The logo: `assets/logo.png` is a generated placeholder (chrome J). Replace `assets/logo.png` (1254×1254) and `assets/logo-mono.png` (white silhouette, transparent) with the real files, then run `npm run icons` and commit (`public/icons`, `android-res`, Android mipmaps are regenerated by `scripts/gen-icons.sh`).

## 1. Supabase (project J)
The org's two free projects are used (35Kb, wann), so creating `J` needs one of: pause/delete a free project, or upgrade the org. Then:
1. supabase.com → New project **J**, region East US (us-east-1). Save the database password.
2. Apply the schema: install the CLI (`npm i -g supabase`), `supabase login`, `supabase link --project-ref <ref>`, `supabase db push` (applies `supabase/migrations/*` in order, including pg_cron/pg_net jobs). Or paste each migration file into the SQL editor in filename order.
3. Deploy every edge function with the shared folder included: `supabase functions deploy --no-verify-jwt ingest-signal tracker-report receipt-action tick scheduler wann-sync` and `supabase functions deploy admin-invite admin-remove-user admin-send-signal admin-push-test` (these verify the user JWT). The `_shared/` folder deploys with each function automatically.
4. Edge Functions → Secrets: `FCM_SERVICE_ACCOUNT` (whole JSON from Firebase step 3.5), `J_ADMIN_EMAILS` (your admin email, comma-separated for several), `J_CRON_KEY` (any long random string), `J_FEED_KEY` (same value as in the wann project, step 7b), `J_SITE_URL` (`https://j-signals.netlify.app` or your custom domain). `SUPABASE_URL`, `SUPABASE_ANON_KEY` and `SUPABASE_SERVICE_ROLE_KEY` are provided automatically.
5. Tell the cron jobs where to call (SQL editor): `insert into private.config (key, value) values ('functions_url', 'https://<ref>.supabase.co/functions/v1'), ('cron_key', '<J_CRON_KEY>');`
6. Authentication → Sign In / Providers → Email: on; **Allow new users to sign up: OFF**; email OTP length 6; OTP expiry 600.
7. Authentication → Email Templates:
   - **Magic Link** (used for the 6-digit code; it must contain `{{ .Token }}` and no link): subject `Your J code`, body from `docs/email-code.html`.
   - **Invite user**: subject `You're invited to J`, body from `docs/email-invite.html` (one button: Confirm my email → `{{ .ConfirmationURL }}`).
8. Authentication → URL Configuration: Site URL = `https://j-signals.netlify.app` (or your domain); Redirect URLs: `https://j-signals.netlify.app/welcome`, `https://localhost/*` (the APK).
9. Authentication → SMTP Settings: enable custom SMTP with Resend (step 4): host `smtp.resend.com`, port 465, user `resend`, password = Resend API key, sender `signals@<yourdomain>`, name `J`. Then Rate Limits → emails per hour: 100.
10. Project Settings → API: copy the Project URL and the anon key for Netlify (step 5) and the APK secrets (step 6).
11. Your admin account is created automatically on the first `tick` run from `J_ADMIN_EMAILS` (within a minute of step 5). Sign in with a code.

## 2. Firebase (project j-signals)
1. console.firebase.google.com → Add project **j-signals** (Analytics off).
2. Add app → Android, package `com.jsignals.app` → download `google-services.json`. It is **not** committed; paste its contents into the GitHub Actions secret `GOOGLE_SERVICES_JSON` (step 6) and copy it to `android/app/google-services.json` for local builds.
3. Add app → Web "J web" → copy apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId (Netlify env vars, step 5).
4. Project settings → Cloud Messaging → Web Push certificates → Generate key pair → the public key is `VITE_FIREBASE_VAPID_KEY`. Check that Cloud Messaging API (V1) is Enabled.
5. Project settings → Service accounts → Generate new private key → paste the JSON into the Supabase secret `FCM_SERVICE_ACCOUNT`. Never commit it.

## 3. Email domain (Resend)
resend.com → Domains → add your domain → add the DNS records (SPF/DKIM TXT, MX for bounces) → Verify. API Keys → Create (sending access) → that key is the SMTP password in Supabase step 1.9. Optional: point `app.<yourdomain>` at Netlify (CNAME) and set it as Site URL / `J_SITE_URL` / `VITE_SITE_URL`.

## 4. Netlify (site j-signals, already created)
1. Site configuration → Build & deploy → link the GitHub repo `KenhighRDS/J`, branch `main`, build `npm run build`, publish `dist` (netlify.toml carries the SPA redirect and the service-worker headers).
2. Environment variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_STORAGE_BUCKET`, `VITE_FIREBASE_MESSAGING_SENDER_ID`, `VITE_FIREBASE_APP_ID`, `VITE_FIREBASE_VAPID_KEY`, `VITE_SITE_URL`, `VITE_RELEASES_LATEST_JSON` (`https://raw.githubusercontent.com/KenhighRDS/j-releases/main/latest.json`), `VITE_RELEASES_PAGE` (`https://github.com/KenhighRDS/j-releases/releases`).
3. Deploys → Trigger deploy (values only reach the next build).

## 5. Android signing + APK workflow (GitHub Actions)
1. Make the release keystore once and keep it forever (updates must be signed with the same key):
   `keytool -genkeypair -v -keystore j-release.keystore -alias j -keyalg RSA -keysize 2048 -validity 10000`
2. Repo → Settings → Secrets and variables → Actions → secrets: `ANDROID_KEYSTORE_BASE64` (`base64 -w0 j-release.keystore`), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` (`j`), `ANDROID_KEY_PASSWORD`, `GOOGLE_SERVICES_JSON`, all the `VITE_*` values from step 4.2, and `RELEASES_TOKEN` (a fine-grained PAT with Contents: write on `j-releases`). Variables: `RELEASES_REPO` = `KenhighRDS/j-releases`, `SITE_URL`.
3. Build: push a commit whose message contains `[apk]` or `[release]`. The workflow builds, signs, uploads `J-<version>.apk` to a release in `j-releases` and rewrites `latest.json` (version, versionCode = run number, url, notes). Bump `version` in `package.json` for a new user-facing version.
4. Local debug build: `npm run build && npx cap sync android && cd android && ./gradlew assembleDebug` (needs `android/app/google-services.json` and the Android SDK).

## 6. MT5 on your PC / VPS
1. Copy `ea/J_Signal.mqh` to `MQL5/Include`. Put your EA sources in `ea/source/` (they are integrated with the three lines in `ea/README.md`; trading logic untouched). Compile in MetaEditor.
2. Tools → Options → Expert Advisors → Allow WebRequest for listed URL → add `https://<ref>.supabase.co`. Keep algorithmic trading on.
3. J → Admin → EA sources → Add EA → copy the key (shown once) → paste into the EA input `InpJKey`; the URL is `https://<ref>.supabase.co/functions/v1/ingest-signal`.
4. Attach the EAs; send a test with `J_SendTest(...)` from the EA or Admin → Send (Test on).
5. Windows: sleep Never; keep MT5 running (a VPS is safer for 24/5).
6. Compile `ea/J_Tracker.mq5` and upload `J_Tracker.ex5` to the `j-releases` repo (the app's tracker page links to the releases page).

## 7. Your phones (and what subscribers do)
- **Android**: download the APK from the releases page → allow installs from this source → open → sign in with the code → Settings → Alerts and permissions: Notifications, Full-screen alerts, Display over other apps, Battery unrestricted, Samsung "Never sleeping apps", optional Do Not Disturb → **Test alert**, lock the phone, wait 10 s.
- **iPhone (iOS 16.4+)**: open the site in Safari → Share → Add to Home Screen → Add → open J from the icon → sign in with the code → Settings → Enable notifications → Allow → Send me a test → lock the phone. Add J to the allowed apps of any Focus mode.

## Acceptance checklist
Automated here: schema and receipt rules (`supabase/tests/run.sh`), lot math (`npm test`), type-check and build, Android compile. On your phones:
- [ ] Invite → email from your domain → confirm → code login works; a non-invited email is refused.
- [ ] Close and reopen after 7+ days → still signed in (web, installed iPhone app, APK).
- [ ] iPhone, app closed, locked: test signal → banner + sound within 5 s; not opened → re-rings every 30 s until expiry; tap → card opens directly.
- [ ] iPhone, app open: exactly one notification; the card updates live.
- [ ] 10 signals in a row on iPhone → 10 separate alerts, permission still granted.
- [ ] Android, app killed, locked: full-screen call alert with ringtone + vibration until Open/Skip/expiry.
- [ ] Android, unlocked in another app: alert pops over it (overlay granted) or the call-style heads-up keeps ringing.
- [ ] Android Skip and the close-question Yes/No work with the app killed.
- [ ] Card fits without scrolling at 360×640; every copy puts the exact value on the clipboard; lot math matches a hand calculation for XAUUSD and USDJPY.
- [ ] Swipe locked until all four copies or 10 s; swipe → taken; Skip → skipped; never opened → missed at expiry.
- [ ] Tracker EA (investor password) opens a matching position → receipt becomes taken; balance syncs.
- [ ] Follow-ups reach only taken/likely users.
- [ ] EA retry: disconnect internet, open a trade, reconnect → the signal arrives once.
- [ ] Weekly report at Friday 17:00 New York; share image 1080×1350 with the logo; test signals excluded.
- [ ] Removing a user signs them out everywhere and stops their pushes.
- [ ] Block XAU for one user → no XAU signal, follow-up or report line for them.
- [ ] Wann off by default; on → every 85%+ game of the next 7 days in one alert, then each new one; off → nothing more.
- [ ] A Wann call that drops below the rule → withdrawn push; a finished game → Won/Lost and the close question.
- [ ] Admin shares a closed EA call and a Wann call in both formats; Hide levels blurs a live call.
